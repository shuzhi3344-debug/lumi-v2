# Lumi v2：效果闭环

本仓库是 Part B 实践部分的交付。v2 只做一件事：让商家看到**每条帖子带来了多少订单**，并据此生成下一条。依据是题面数据：22% 的付费用户反馈“不知道发了有没有带来订单”，全渠道付费 30 日留存只有 26%。

## 目录

| 路径 | 内容 | 怎么看 |
|---|---|---|
| `prototype/index.html` | HTML 可点击原型（基础交付） | 浏览器直接打开，顶部可切换「Pro 商家」「Free 商家」两个场景 |
| `docs/PRD.md` | 产品文档，按题目要求的 8 项组织 | 直接阅读 |

## 运行可运行版本（`app/`）

需要 Python 3.9 及以上，以及一个支持 function calling 的 OpenAI 兼容接口的 key（默认 DeepSeek，也可换成 Kimi 或智谱 GLM，见 `app/README.md`）。

```bash
cd app
cp .env.example .env              # 1. 打开 .env，填入 LLM_API_KEY
pip install -r requirements.txt   # 2. 安装依赖
python main.py                    # 3. 打开 http://127.0.0.1:8000
```

建议用带广告参数的地址打开，以体验来源捕获：`http://127.0.0.1:8000/?utm_source=tiktok&utm_campaign=spring_sale&ttclid=TT123`。完整体验路径（约 3 分钟）见 `app/README.md`。

### 加分项对照

| 题目要求 | 实现 |
|---|---|
| 前端聊天框多轮对话 | 对话历史含工具调用记录，可以接着上一轮说话 |
| 后端调用大模型、至少 3 个 tool、由 Agent 自主决定 | 5 个工具，通过 function calling 由模型自主选择，没有 if/else 路由 |
| 商家数据 mock | `app/data/`：商品、评价、历史帖子表现 |
| 免费额度在后端生效 | 调用模型前原子扣减；效果数据和追踪功能按套餐在后端拦截 |
| 关键事件真实上报和记录 | 10 个事件写入 SQLite，可在「埋点记录」页查看 |
| 落地页捕获 UTM，并在注册 / 付费事件中带上 | 服务端写入第一方 cookie（首触与末触），注册时落库 |
| `.env.example`、启动不超过 3 步 | 见上 |
| 工具调用过程可见、结构化卡片、流式输出、异常处理 | 均已实现 |

另外实现了从短链点击、模拟 Shopify 下单到订单归因的完整闭环：优惠码优先、7 天归因窗口、幂等、退款扣回。`app/tests/test_app.py` 为端到端测试，用脚本化的模型替身覆盖这些规则：

```bash
cd app && pip install pytest && python -m pytest tests -q
```

## 说明

- 仓库中不包含任何真实 API key，`.env` 已加入 `.gitignore`。
- Shopify 授权、支付和订单 webhook 为模拟实现，接口形态按真实流程设计。
- 原型、文档和可运行版本使用同一套数据：5 条历史帖子，共 1,862 次点击、23 单、$1,140。
